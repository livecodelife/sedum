# Lifecycle demo

A runnable end-to-end check of hash-aware `sedum grow` and `provenance migrate`,
on a small Go app built with this repository's own `testdata/generators/chi`
package. It uses a local stub model, so no real model is ever called and runs
are deterministic.

```bash
evals/lifecycle/demo.sh
```

The script:
- builds sedum from this checkout, sedum v0.8.0 from this repository's history,
  and the provenance CLI from `github.com/livecodelife/provenance` at a pinned
  commit (`PROVENANCE_REF`);
- runs three sequences, each in a fresh scratch app under `evals/lifecycle/work/`;
- prints a pass/fail table, and exits 1 if any step fails.

It needs go, python3, git and curl. linespec is optional: only the v1-record
lint step uses it.

| Sequence | What it shows |
| --- | --- |
| sedum | First grow; a second grow with 0 model calls and no file touched; editing one record regenerates only its file; a template change re-renders with 0 calls; `grow --check`; the region-ownership error; `--force`; `--prune-orphans` for deprecated and deleted records |
| migrate | v1 supersession and a bug, `provenance migrate` (7 records → 5, aliases, versions, version manifest), then a grow that regenerates only the changed record and rewrites alias markers to the survivor |
| pre-gen | Markers written by sedum v0.8.0 (no `gen`) cost one full re-selection; `grow --stamp` makes them current with 0 calls |

**Files**
- `run.sh`: every step as a function that asserts and exits non-zero on the first
  failure. Run `./run.sh step0 step1 step2 …` to step through by hand.
- `stub_router.py`: the stub OpenAI-compatible model. It picks a canned answer
  from `fixtures/answers/routes.json` by text in the prompt, and logs each call,
  which is how "no model calls" is checked.
- `fixtures/stepN/records`: the v1 records each step adds, generated by
  `make_records.py`. They're stored as `<hex>.yml`, without the `prov-YYYY-`
  prefix, so this repository's provenance hook doesn't lint them as its own
  records; `run.sh` restores the name in its scratch app.
- `table.py`: prints the result table.

Origin and the full plan: the Provisio lifecycle testbed (provisio-mgr, #provisio).
